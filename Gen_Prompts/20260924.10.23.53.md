## 任务目标
修复 `bash scripts/e2e_golden.sh` 在 Windows 上被 WSL 接管、使用 WSL 的 Python 3.10 运行 cypyc 导致 23 个示例全 FAIL（PASS=0）的问题，使外部判据在当前机器原生 Python（Windows Python 3.13）下真实运行并恢复基线（PASS>=20、FAIL=0）。

## 背景
- 项目根：`E:/IDEProjects/AI/Cypy`；判据：`bash scripts/e2e_golden.sh`。
- 本机 `bash` 是 WSL bash（启动输出 `wsl: 检测到 localhost 代理配置` 噪音），其内部 `python` 指向 `/usr/bin/python`（WSL Python 3.10），而 cypy 编译器及依赖安装在 Windows Python 3.13。
- Windows PowerShell 下 `python -m cypyc run examples/hello.cypy` 成功输出 "Hello, World!"（exit 0）——内核可用。
- WSL bash 下 `python -m cypyc run` 对 23 个示例输出编译错误或与 golden 不一致？ summary `PASS=0 FAIL=23`，退出码 1。
- 该判据被 FIST-Mbt `[gate:required]` 硬门禁用于验收（run_check 直接调 `bash scripts/e2e_golden.sh`）。

## 具体要求
1. 诊断本机 bash 是否指向 WSL；确认哪个 shell 能访问 Windows 原生 Python（优先 Git Bash / MSYS2；否则用 Windows python 绝对路径，如 `py -3` / `python.exe`）。
2. 改造 `scripts/e2e_golden.sh` 顶部显式锁定 Windows 原生 Python（`export PYTHON=<Windows python 绝对路径>`），使 `CY()` 用该解释器而非被 WSL 劫持。
3. `bash scripts/e2e_golden.sh` 应恢复真实编译器输出；若个别示例真失败需修复或如实标注，不得弱化判据。
4. 若个别 golden 因行为变化需更新，用 `--update` 落库（必须是程序真实 stdout）。
5. 最终 `bash scripts/e2e_golden.sh` 达 PASS>=20 且 FAIL=0；若确有编译器缺陷无法全绿，至少消除 WSL 全红假象并如实报告剩余真实 FAIL 及其根因。
