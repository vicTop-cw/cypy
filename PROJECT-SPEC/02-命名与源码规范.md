# PROJECT-SPEC/02 — 命名与源码规范

> 本文件规定 FIST 下发的项目级任务的命名、错误处理、依赖与注释风格。**AI 生成或修改的代码必须符合本规范。**

---

## 1. 命名规范

| 类别 | 规则 | 示例 |
|------|------|------|
| 函数/方法 | snake_case | `tensor_add`、`lower_ghost` |
| 类型/类 | PascalCase | `GhostIr`、`TnrError` |
| 常量 | SCREAMING_SNAKE | `MAX_RETRY` |
| 模块/包 | snake_case 单数 | `frontend`、`omega` |
| 私有项 | 下划线前缀（Python） | `_inner()` |

## 2. 错误处理

- 所有可能失败的操作返回结构化错误（异常/Result），不静默吞错；
- 错误信息必须可定位：含模块、操作、原因；
- 禁止用 `except: pass` 掩盖错误；确需忽略时必须注释原因。

## 3. 依赖规范

- 版本全部精确锁定（`==` / `=精确版本`），锁文件入库；
- 优先标准库/已安装依赖，不自研可复用内核（拿来主义借力）；
- 新增依赖需在 CHANGELOG.md 记录。

## 4. 注释与风格

- 中文注释（与 FIST 项目一致）；只注释"为什么"，不注释显而易见的"是什么"；
- 保留既有中文注释与命名习惯；
- 提交前跑 lint/format（如项目配置），0 warning 优先。
